## 失败与修正

首轮CI36107035081的49个Agent集成场景通过，但迁移演练失败：0003验证SQL给出了两个结果集，迁移工具按单结果集读取rows。随后统一为单查询，进一步按既有接口要求返回布尔verified=true（不是整数1）。只修改本PR新增0003验证语句及摘要，0001/0002、迁移工具及原断言均不变。

额外自审发现签发等待资源锁后可能沿用先前会话或临时资源权限。现于签发返回前重查全部资源权限、期限，以及根签发人的当前会话或子签发的祖先链；失败回滚整个事务。新增两个真实PG场景用pg_stat_activity确认等待：会话空闲期限在等待时届满；先检查的受限资源授权在等待第二个资源时自然到期。两者均确认没有残留Delegation或Snapshot。

## 关键已验证行为

- 子级不能扩大资源、动作、环境、起止、深度、额度或责任人；同一Agent不能重复出现在祖先链中。
- 四个并发兄弟分配6次额度、父总额10次时仅一个成功；六个并发工具调用、额度2次时仅两个成功。
- 相同request_id的并发改名仅一次实际变更和扣额；不同内容重用请求号冲突；回执写入失败时目录与额度同事务回滚。
- 三层授权根撤销后子孙均拒绝；祖先Agent停用、责任人身份停用再启用、成员变更、组织停用再启用、策略更新不能复活旧授权。
- 临时资源授权自然到期，即使policy_revision未改变，实际调用仍拒绝；请求等待资源锁期间授权到期同样拒绝。
- 重试读取历史回执前重新授权；撤权后不能借旧请求号取回旧内容。重试的回执是历史结果，不声称当前资源状态。
- 凭据只初次签发返回，库内只有摘要；运行角色不能改写/删除快照、回执或改变凭据和责任人；响应检查与日志检查无秘密外泄。

## 验收边界

仅本机可信控制面及目录读取/改名，不是生产认证、OAuth兼容、实际MCP、文件执行或OS沙箱。Agent不是模型本身，登记Agent不会启动模型。调用额度是成功目录工具次数，不是Token/货币/供应商费用或组织总预算；子额度撤销不自动退款。

快照SHA用于完整性核对，不是签名或抵抗管理员改写；运行角色受列级权限限制，但可信服务器数据库连接不是给不受信任Agent使用的能力。事务锁仅约束遵守同协议的仓储，不能约束管理员直接SQL。授权树使用组织级串行，非吞吐性能认证。

显式委派独立于浏览器会话，logout不取消授权；责任人/成员/组织及祖先撤销会阻断后续调用。撤权不能撤回已返回数据或已提交事务。重连测试为仓储重建/Fastify重建，不是Agent进程OS SIGKILL恢复；少数真实TCP请求不是压测。

没有权限UI、企业登录、实时撤权推送、审批签发或真实多模型执行。关闭ZENTWINE_AGENT_MODE回退并保留数据；0003有损down不能自动用于真实业务数据。既有GitHub分支保护管理权限限制未改变，CI是只读且未增加凭据豁免。
