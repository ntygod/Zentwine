## 集成结果

| 场景 | 结果与证据含义 |
|---|---|
| 并发重复命令 | 8 个相同请求只有 1 个首次创建、1 个 start outbox；内容冲突被拒绝，组织 scope 分开 |
| 事务失败 | 业务记录与 outbox 一起回滚；之后可重新提交 |
| 启动应答丢失 | Temporal 已创建流程但本地未确认，再派发复用同一个 runId |

| 提交后崩溃 | 数据库已提交而 Activity 结果未确认时 SIGKILL，实际至少执行两次尝试，效果行仍只有一条 |
| 完成后重派发与回放 | 已完成流程不创建替代执行；真实历史 deterministic replay 通过且不重复 Activity 副作用 |
| 未授权信号与拒绝 | 只有通知不能放行；拒绝不可被后续相反决定覆盖，业务副作用为零 |

## 可重复性与锁文件

历史上使用一次数据导入 workflow，将已知 artifact 中经过固定大小和 SHA-256 校验的锁文件写入本工作分支。该临时作业未 checkout/运行仓库代码，仅拥有此次导入所需的 `contents: write` / `actions: read`，目标分支和文件固定；未合并 main。导入作业已经从最终分支删除。长期验证 workflow 仍为 `contents: read`，不回写仓库、不使用用户 Secrets。

## 边界与残余工作

Temporal 开发服务把历史保存到 SQLite，业务权威记录使用 PostgreSQL；没有测生产 Temporal 使用 PostgreSQL 的集群部署、高可用或备份。等待不是实际运行数月的证明。活动可能重复，实验只证明本地事务内的合成效果幂等，不证明任意外部工具 exactly-once。
