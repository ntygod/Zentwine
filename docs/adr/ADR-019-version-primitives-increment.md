# ADR-019｜独立交付版本规则与摘要，不携带被阻断迁移

状态：Accepted（只接受增量拆分与纯函数边界；对应PR通过精确CI后交付）。

## 背景

ZT03-02草稿PR #33的0009使用PL/pgSQL，现有迁移门禁拒绝函数体内的BEGIN。上一轮函数块识别扩展写入被工具拦截，原门禁保持不变。数据库候选、触发器、CAS与32项PG测试尚未验收。版本规范化和摘要本身没有数据库依赖，不应被误报为数据库能力，也无须和0009一起上线。

## 决定

从已验证main另建A增量，只交付纯领域类型/规则、受限规范化、深度冻结命令快照及Node摘要适配。Node crypto仍在现有db适配包，纯domain不引入Node或供应商依赖；摘要模块不连接数据库。保留现有TenantUnitOfWork和所有业务路由，不暴露尚无实现的版本持久端口。

0009、写命令、不可变触发器与原32项真实PG验收留在PR #33草稿，不以SQL编码或隐藏语句适配正则、不修改或绕过被拦截门禁。Issue #32保持打开且完整要求不删减，ZT03-03不推进。不存在“把A标Done后顺带关闭B”的验收替换。

## 取舍与恢复

代价是PR #33后续必须与主线整合，复用摘要/快照函数并消除重复导出；在它的最终精确head重新执行真实PG及全量CI。当前不能让用户通过页面或API并发修改持久内容，也不能证明旧批准不会在数据库应用到新内容。A的有限转换规则不是权限检查。

A无数据库迁移、业务写入或外部调用，回退只涉及代码与导出；已有使用者需先移除相关调用。固定规范版本不可在后续静默修改，以黄金样本守住兼容。未新增依赖、冻结锁、质量门禁或生产权限变更。本次为受托实施和自审，不是独立第三方认证。
