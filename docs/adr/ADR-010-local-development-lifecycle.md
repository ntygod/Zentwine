# ADR-010｜本地开发与故障环境生命周期

状态：Accepted（限定本机开发工具设计）。日期：2026-09-24。关联ZT01-06；项目负责人已授权实施者技术决策，实施验证结果与合并状态另记录。不批准生产发布。

## 决定

保留宿主机 Workbench/Studio/API 的无数据库启动路径；新增独立 Compose 基础服务，提供 testkit与既有workflow实验所需的两个合成数据库，不把基础设施联机当成业务持久化已经实现。

同一checkout的手动环境可复用；故障演练每次生成独立session、项目名、owner标签、随机本地凭据和端口。用本地flock串行修改状态，以socket+daemon ID+Compose摘要+资源标签限定清理。停止只涉及本次进程组和本项目资源，不用prefix扫描、system prune或任意PID杀进程。

工具准备与执行分开，CLI固定归档与可执行字节校验；显式支持离线缓存校验。诊断分fresh/app/integration/faults，提供JSON但不执行修复。原测试直接调用仍保留，新入口调用它们而非复制或削弱断言。

## 备选

整个应用容器化会改变尚未完成的身份/开发热更新边界，当前不选。每次复用同一测试数据库容易串数据，不选。仅写一组命令而无状态和清理检查，不能满足异常恢复，不选。用PID文件自动猜测旧进程会出现PID重用风险，因此采用内核文件锁且不删除锁inode。

## 代价和边界

当前限定Linux；flock与Docker是可信本地工具，Docker socket不是安全沙箱。SIGKILL/断电/daemon断开仍可能留下容器，依赖可核对session的显式清理。检测到资源归属、daemon或配置改变则失败关闭，不为了清干净扩大删除范围。

旧Spike写共享报告目录，统一入口对此独立加锁；不能阻止用户绕过入口手工并发运行它。原数据库用例基于可信测试租户设置，不是生产身份系统。尚不引入Redis、对象存储、生产Temporal集群或真实模型。

## 验证与回退

新增工具单测、真实应用生命周期、Compose重复/并行/异常清理、统一数据库和耐久故障入口；原质量总门禁不变。失败时修复实现或明确保留未完成项，不移除原断言。回退本PR恢复原开发命令；回退前先用本版本清理本机session；无生产迁移。
