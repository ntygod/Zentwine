# ADR-017｜显式事务绑定的租户数据访问层

状态：实现候选；最终验证和合并见ZT03-01 PR。日期：2026-09-26。责任：受托开发实施与自审，不表示第三方独立审核。

## 决策

为新业务原语新增独立数据schema和运行身份；旧控制面不在此轮批量重写。RLS作用于对象标识与关联，主键/外键包含org_id，运行角色只有读取/新增权限。没有通用JSON内容列，不代替后续业务版本和授权设计。

不使用未经数据库验证的 `SET app.tenant_id`：角色即使不能BYPASSRLS，仍可能设置自定义参数。选择私有、按backend PID/xid8/login_role绑定的上下文表，通过固定definer函数验证当前组织会话后写入；公开SQL不能直接访问该表。每个事务只绑定一次，结束清除凭据，下一事务/连接不能复用。

运行账号不得拥有表/schema/函数、继承角色或读取身份凭据表。函数使用全限定名称和固定pg_catalog/pg_temp搜索路径，PUBLIC执行权撤销，普通账号不能修改函数。迁移身份可更新结构，故始终与运行pool分离；不声称能防恶意DB管理员。

复用现有会话行和授权advisory锁顺序，数据库函数在获得锁后复核，并在repository结束前再次检查。已开始的合法事务可先于后来的撤权完成，不承诺在途已返回数据回收或强杀其他进程。

## 代价与替代方案

每次绑定和授权复核产生数据库查询，私有上下文有事务性写入；当前仅支持主写数据库上的短事务，不支持只读副本和导入任意SQL。清理按连接退出和下次绑定执行，无长期会话凭据留存承诺适用于正常repository路径；直接SQL客户端若自行提交未结束的绑定，私有表可能暂存摘要，但xid绑定仍防重用，下一次清理删除。

逐租户数据库登录可强化物理边界，但连接池和大量角色运维成本更高，当前不采用。纯GUC配合可信服务可以减少查询，但不能在SQL凭据泄漏时证明上下文不可伪造，当前不采用。为所有旧控制面一次性加RLS会改变登录/跨组织选择语义，须独立规划，不混入本PR。

## 回退与范围

0008空表可事务回退；出现业务标识后必须向前修复，避免回退删除数据。同一PR不改历史迁移、旧测试或门禁。资源细粒度授权、版本/CAS、语义关系、outbox及Operation另属后续任务；ZT02-06完整文件/预览/导出验收保持打开。
