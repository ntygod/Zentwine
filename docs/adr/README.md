# 架构决策记录

状态：以下全部为 Proposed，尚待对应负责人批准。状态可取 Proposed / Accepted / Superseded / Rejected；不能由实现 Agent 把自选方案默认为 Accepted。

| ADR | 决定 | 验证要求 | 否决或替代条件 |
|---|---|---|---|
| ADR-001 | TS monorepo、模块化控制面、独立 Runner/Verifier，Temporal 候选 | 固定版本 POC：故障恢复、事件重放、持续人工等待、取消与重复启动 | 无法满足私有部署/运维成本时替换持久流程实现，保留 WorkflowPort |
| ADR-002 | PostgreSQL 为业务权威，版本不可覆盖，outbox/inbox | 并发批准、版本冲突、租户隔离、未知远端结果 | 不能以最终一致事件取消必要事务；对需强一致动作局部事务保护 |
| ADR-003 | Workbench/Studio 分入口；一工作区一写入租约 | 两窗口、两控制者、旧进程恢复、断网失联 | 无法证明旧进程停止则隔离，不允许第二写入者 |
| ADR-004 | 每供应商独立适配器，共同能力契约 | 两基座真实并行、鉴权、工具拒绝、停止、交接、费用回传 | 缺关键控制则不允许该任务；新增受控方式不伪装原生能力 |
| ADR-005 | 验证独立，证据绑定候选版本 | 测试删减、旧提交报告、伪造模型结论 | 未通过可信检查不能推进必要发布门禁 |
| ADR-006 | 自治/插件使用版本化授权和最小权限 | 子授权、插件撤销、注入、预算、应急停止 | 无法限制资源或撤回就不得进入受控交付模式 |

每个 ADR 的正式评审提交需填写背景、备选、选定方案、影响、验证报告、负责人、决定日期和替代关系。可以使用 [ADR 模板](../templates/adr.md)。
