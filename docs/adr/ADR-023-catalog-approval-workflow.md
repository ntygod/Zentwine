# ADR-023｜目录改名的独立审批交互

状态：限定代码验收通过（CI36247497495），最终文档提交复验及合并见PR #43；范围ZT04-03-B1，Issue #42。前置PR #41已合并。父Issue #40仍InProgress。

## 决定

复用ZT02-04已验收的目录操作审批，而不是为界面复制数据库权限、引入0009或把读取判定变成批准。单独的申请/审批路径承载写入确认，资源详情本身仍只读。目录审批绑定catalog.rename与目录版本，和内容修订批准明确区分。

新建申请始终要求独立审核；审批与执行各自需要用户明确确认。执行许可不进入React状态或持久存储。审批记录、确认守卫和绑定摘要严格核对；未知响应只通过读取对账，不自动重复写入。已签发但丢失的许可采用明确撤销后重建，不绕开一次性限制。

## 取舍

沿用成熟后端可交付真实双人闭环而不解除通用内容CAS阻断。代价是只支持目录改名、暂无待办列表与通知，审核人需获知定位链接。创建回执丢失仅支持当前窗口同请求恢复，不声称跨设备或重启恢复。已展示内容不可远程抹除，浏览器事件只用于失效提醒而非授权。

应用调用一次不等于网络发送一次。真实响应头前故障场景已观察到HTTP重传，故防重复效果依赖已有服务端版本、一次性许可和持久回执，不承诺仅凭前端锁实现网络exactly-once。

30项新合成响应测试、13项新真实Chromium＋PG和2项默认浏览器场景通过，并保留全量旧回归，详见[验收报告](../testing/zt04-03-b1-report.md)。首轮过期fixture和传输次数失败已修复，未削弱原权限或约束；最终文档提交仍须完整复验。
