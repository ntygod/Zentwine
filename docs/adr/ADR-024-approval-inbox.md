# ADR-024｜目录审批的受控发现与创建界限分页

状态：Proposed；Issue #44。代码候选必须经过精确提交完整CI后才能验收；最终状态见关联PR。

## 背景

B1已有单申请的提交、独立审核和执行，但只有已知ID才能进入。旧approval-events仅通知申请人和已参与决策者，不能代替负责人的待审发现。将所有事件拉到浏览器再过滤既不完整，也扩大披露面。

## 决策

增加只读GET索引，沿用B1详情可见性：有效非访客人类身份、当前组织、本人申请或有效负责人，以及目标资源当前resource.read允许。先在SQL限制可见范围再分页，在既有事务中复用策略求值和结束前会话检查。不改变批准/执行权限，不引入“列表存在即有权批准”。不返回隐藏数量和全局序列。

使用既有首次事件唯一键作为申请创建排序；bigint以字符串处理。审批事件流锁保证规范写入与读取创建界限有顺序，资源锁按ID排序；不改历史迁移、不另增一套内容版本。当前授权和记录状态逐页重新核验；创建范围固定不等于一致历史快照，权限/状态移动后允许刷新，不宣称实时任务总数。

服务端实例密钥加密认证的15分钟游标绑定身份、租户、会话、授权版本和查询。重启游标失效是明确取舍；密钥持久化、多实例无粘滞路由与大组织分页性能属于后续部署设计，不能宣称当前已完成水平扩展。游标不是访问凭证，失败不自动改范围。

前端独立控制器只做读取与明确组织切换，每次加载先删除旧投影。列表只链接B1详情，不做批量决策；不将GET引入隐含业务写。未知/错误不回退显示上页旧记录。现阶段返回的名字是拟登记名称，目录绑定版本不是正文修订。

## 替代方案与后果

没有以通知事件流模拟审批列表，也不引入通用搜索、全文正文或跨组织索引。创建序列无需新schema，代价是现有索引和组织流锁下的查询负载；当前默认每页20、最大50，未做生产量级性能认证。权限更改可能使游标需要重开；长期可追溯历史仍留在已有审批详情与其他工作包中。

运行账号授权与原schema不变；直接管理员SQL绕开协作锁不在保证范围。该ADR不解除通用版本数据库迁移阻断，也不缩减父任务范围。
