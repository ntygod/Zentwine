# ADR-018｜不可变内容修订与 CAS 状态快照

状态：Proposed／Blocked，未验收代码候选，最终验收与合并见 Issue #32 对应 PR。前置 ADR-017 和 ZT03-01。

## 决策

在现有租户事务上增加独立 zentwine_versions schema。内容修订、状态快照、版本关系均只追加；数据库执行的唯一写命令负责合法转换、对象锁、expected_version 比较和操作人归因。应用运行账号只能 SELECT/EXECUTE，固定 definer 由现有受控 NOLOGIN/NOBYPASSRLS owner 拥有，表仍启用 FORCE RLS。既有身份/策略/Agent控制面不重写。

内容摘要由独立、限额、版本化规范化函数产生，数据库存类型化描述符而不存万能正文。数字选择安全整数而非完整浮点数协议。UTF-16 排序和保留 Unicode 形式参考 RFC8785，但该受限 v1 格式有独立名称/域分隔，不冒充完整标准实现。

内容 revision_id 与每条状态 object_version 分离。所有命令新增状态快照；状态变化不产生新的正文。批准限制为不同于内容创建人的当前负责人；批准/替代/退休事实不等价执行审批。内容或关系发生变化必须新建修订，禁止复制旧批准。关系目标是精确修订/摘要，不是易变化的当前对象指针。

冲突作为经过外层最终权限复核的结果返回，包含预期与当前版本；不能通过抛出携带敏感快照的异常绕过最终复核。没有自动重试、覆盖、自动合并或幂等成功假象。

## 取舍与边界

Append-only 消除原地改写风险，但存储增长和生命周期清除要由后续保留模块处理。对象锁使同对象并发命令形成明确顺序；跨对象组合调用应排序，死锁返回失败。没有全局事件顺序、outbox、消费者或外部事务保证。隔离级别和锁行为按 PostgreSQL17 的官方事务文档核验，仍以本仓库真实并发回归为验收依据。

数据库仍信任迁移 owner 与服务端领域代码；客户端不得拿到任意SQL或新内部端口。组织隔离不能替代细粒度对象与关系目标授权。摘要不证明外部文件存在、不可篡改签名、生产权限或合法内容，正文必须由所属模块验证。

完整 JSON 浮点规范、可变草稿行、自动 CRDT 合并以及全文通用表均未采用。它们需要另外的明确契约，不能以基础库便利性改变批准不可覆盖和冲突显式处理的规则。

## 验证与回退

规则黄金向量、所有状态/命令组合、真实双会话竞争、RLS及复合外键、拒绝自批、权限撤销/过期、同摘要不同修订、绑定关系、运行权限误授、异常回滚及保护性降级测试。最终提交完整 CI 与制品核验通过后才能接受此限定实现。未使用时事务down；有任何历史则向前修复。

资料：RFC8785 第3节（JSON规范化）；PostgreSQL17 文档13.2/13.4（事务隔离与显式锁）。这不是独立安全认证。

当前未接受：0009尚不兼容原迁移门禁，兼容扩展的工具写入被拦截且未重试；没有基于本地测试宣称数据库回归或完整验收通过。
