# ADR-014｜精确操作审批、职责分离与一次性动作许可

状态：Accepted（本机可信控制面范围）。任务ZT02-04；前置ADR-011、012、013。

## 决定

审批不是角色提升、通用Agent凭据或代码部署许可。当前实际目标是catalog.rename，使用人类会话和组织上下文。请求固化组织、请求人、资源、环境、名称、资源版本、策略版本、身份/成员/组织版本，并用sorted-json-v1与SHA256绑定。新操作或版本须新请求，不覆盖原批准。

当前策略deny永不被审批覆盖；needs_approval要求不同人类主体。审批者必须是组织owner，并且具有目标的读取和操作资格。请求人即使是owner也不能批准自己。review=policy只在真实规则返回allow时记录preauthorized_policy，不把它伪装人工批准；review=required主动要求人工，不允许降低策略要求。

请求期限15分钟，原请求人批准后一次性领取最多2分钟许可。秘密32随机字节，存储仅摘要；不返回给审批者，不支持从记录恢复。领证响应丢失不能重放取得原秘密，应撤销并重新申请。许可只对原主体及原命令生效，不能由Agent bearer消费，不能用于根授权签发。

消费在同一数据库事务内重查当前身份、成员、审批者资格、环境、内容摘要与版本，再写许可消费、目录修改、回执和事件。并发只能一个成功；重放拒绝，历史结果通过读取审批取得，不执行第二次。执行动作的检查不同于评估结果或通知，approved本身不等于已经执行。

## 撤权与通知

审批事件为持久事务outbox，按组织事件锁保证序号分配和提交顺序；用当前身份过滤的游标轮询取得，可重放、可去重。消息没有秘密和操作正文，不赋予权限。

身份/组织/成员和组织策略变更在既有治理仓储事务内调用invalidateApprovals，相关pending/approved/issued记录撤销并同步写事件。旧开发数据库尚无0004时无审批可撤销。若已安装审批库但事件写入失败，整个治理事务失败，不能宣称撤权已完成。

不为本次实现放宽迁移门禁去接受任意数据库函数；使用显式同事务应用代码，而非SECURITY DEFINER触发器。直接管理员SQL不在合作协议保证内，但消费仍复核当前版本。资源版本变更和时间自然到期由消费时强制拒绝，不承诺自动为每次时钟到期或资源漂移发送事件。通知提供持久轮询，不声称硬实时推送。

## 锁顺序和限制

会话行共享锁 → 排序的人类身份锁 → 组织锁 → 排序成员锁 → 策略共享锁 → 组织审批事件排他锁 → 审批行 → 资源行 → 许可行。审批者可能在等待期间变化，重读时若未持其锁直接冲突重试，不隐式追加乱序锁。所有语句使用READ COMMITTED；等待后重新检查。自然过期边界还覆盖许可行等待和回执写入时间。

当前按组织串行审批操作，优先正确性而非大规模吞吐。审批事件不可修改/删除，但可信服务可以插入，摘要不是签名。不能撤回已返回数据或已提交操作；无公网认证、MFA、Agent审批扩权、业务RLS、任意执行器和审批UI。Agent相关高风险步骤仍先停下，由人类通过本审批执行明确操作，不能借人类许可扩大已有委派范围。
