# ADR-030：多输入整批本地交接

状态：接受为 ZT12-01-A6 的限定实现决定；Issue #57，完整验收以对应 PR 为准。

## 背景与决定

A5 只能交接一个选中产物。团队协作中，一个消费者可能同时需要代码、测试与审查产物；单份先交给下游会在其他输入失败时造成半准备状态。因此增加独立 RuntimeInputBundle，覆盖消费者全部 input_artifacts，而不扩展 wire 协议或声称准备全部上下文。

构造预检精确覆盖、唯一生产者/清单、来源和总体字节预算。每生产者复用 A5 检查事件报告一次，再由私有 A4 读取器逐项检查字节。所有报告通过后才开启字节阶段；全部匹配后同步 takeAll，按消费者顺序一次性交出同一组已检查缓冲。公开快照不包含字节。

多来源可并行，但任一失败或取消都关闭全体读取器并擦除仍拥有的内容。生命周期 Abort 覆盖两个阶段及间隙，迟到读取/摘要不得把 rejected/closed 恢复为 ready。无输入的合法计划交空包而非运行许可。

## 取舍与边界

保守地等待全部生产者报告，可能降低流水线并行度，换取可说明的输入就绪边界。复用 A5 的报告校验会创建一个不执行字节阶段的内部读取器，受固定生产者数量限制，避免复制旧判定逻辑。总输入字节有独立上限，原每流/每项限制仍保留。

不采用 ReadableStream.tee 向多个消费者重放同一生产响应，不增加隐藏缓冲；不接受调用方构造的“已验证”快照。默认不自动获取来源，不做调度、批准或补偿。交接结果不是来源认证和执行许可；本实例一次领取不是持久事务。

## 验收与回退

验证并发顺序、完整覆盖、同源多产物、半成功禁止领取、失败擦除与挂起取消、迟到摘要、精确预算以及真实 loopback HTTP 组合。所有旧读取器/测试和门禁不改。需要回退时撤销本新增类和导出即可，不涉及迁移或已存数据。父 #46 的持久联调和真实宿主条件不变。
