# ADR-026｜连续前缀运行观察与执行权分离

状态：Accepted（限定只读实现；精确完整CI与合并以PR #50为准）。关联Issue #49 / 父Issue #46，承接[ADR-025](ADR-025-runtime-wire-contracts.md)。原ZT03-02及Issue #32/#35的依赖不删除。

## 问题

单条RuntimeEvent合法不能证明一段事件历史合法。直接把最后到达的事件作为当前状态，会让乱序成功覆盖停止、重复用量被多算，或把来自另一Attempt的报告拼进当前任务。此前wire1.0.0只有消息结构/绑定检查，没有有序消费实现。

## 决策

在已有client包新增RuntimeEventObserver，不修改wire1.0.0，也不为未实现宿主新增依赖或空壳运行API。通过公开contracts同步解析并冻结，绑定一个组织/Run/Attempt和来源，只接收从1开始的连续序列；事件ID精确去重，内容或序号矛盾失败隔离。BigInt用于序号，不依赖事件时间。

报告状态与覆盖状态独立：reported_state只是最后合法报告，synchronization明确前缀连续、需补读、需核验或已关闭，authorization始终false。缺口不缓存正文，只要求显式重放；不信任任意检查点或把网络恢复当作新执行。unknown与矛盾不能自动恢复；停止请求与取消回执不同，取消及成功仍是声明，不是进程停止/业务完成证明。

输入应答绑定唯一请求，旧请求不得跨阶段或跨通道重用；摘要及工具请求不执行动作。产物固定精确引用，最新用量不自动累加。默认1024事件/1MiB规范化串预算，最多64产物；可调低，不能调高。预算不等于JS堆上限。超限不通过淘汰历史维持“去重”假象。

所有守卫通过后才修改实例；close清空其拥有的上下文/集合/投影，旧副本不能被远程撤回。退出登录和切上下文的宿主负责调用close。接口不监听网络、不包含fetcher/Storage/定时器或外部写入。

## 代价及后续

本观察profile比单消息schema更严格：终态后的用量或补发新事件不自动接受；观察到unknown后即使收到成功也要求核验。适配器需规范事件顺序和稳定ID，或走显式inspect/持久对账，不修改本地状态掩盖差异。

实例内记录不能代替数据库inbox、跨窗口/重启恢复、生产量级长历史、租约/预算/授权或消息真实性。故障投影保留最后合法前缀用于说明，消费者不可当作当前可执行状态。后续受保护检查点和宿主能力另行设计/验收，不把此增量当完整ZT12-01关闭条件满足。

测试覆盖公共入口、96项状态决定、全三事件投递排列、精确容量、身份/来源/冲突及未知结果。没有新增UI截图或真实模型证据。撤回只需移除新增导出与文件，无数据库回退。原测试、旧协议、迁移与CI检查均保持。
