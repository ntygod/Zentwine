# ZT16｜异构多模型编排与协作通信

状态：Planned。负责人职责：执行平台、后端、质量、产品。依赖模块：ZT03、ZT12、ZT13、ZT14、ZT15。对应蓝图：08、14.4、17。

## 目标

实现真正同时使用不同模型、不同基座的协作；支持并行、接力、独立验证、人机结对、多方案比较、有限讨论、分层委派和跨团队交接。共享目标与事实，执行互相隔离。模型提议计划，平台验证并持久化。

## 工作图与状态

FlowRevision 包含 node(kind,inputs,outputs,role,binding,policy,budget)、edge(condition,artifact_schema)、join_rule(all/any/quorum_with_policy)、loop_limit 与 compensation。必需节点失败不可被其他成功掩盖；any/quorum 只能用于明确允许替代的节点，不能代替必要质量。

FlowRun、NodeRun、Run/Attempt、Message、ArtifactConsumption、Reservation、CheckpointRef 共同保存进度。业务节点允许有限循环，循环有次数、预算和退出条件。Temporal 等引擎只执行控制，不能代替业务批准。[S04]

## UI 与接口

`/flows`、`/flow-runs`、`/flow-runs/{id}/messages`、`/nodes/{id}/artifacts`、`/nodes/{id}/enter-workspace`。执行图、列表、产物、检查点、成本、审批和协作消息共享同一事件；UI 不用估算百分比掩盖未知。

## 关键失败测试

两个节点抢同一环境；供应商限流；一节点先成功另一节点失败；审批时重启；重复产物；缺 schema；伪装已批准的消息；子 Agent 未回报费用；过期租约恢复。真实异构验证必须有版本报告，不用两个 Fake 或同模型改名代替。
