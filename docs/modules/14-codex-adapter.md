# ZT14｜Codex 适配与自有交互

状态：Planned，未进行真实供应商测试。负责人职责：执行工程、安全、质量。依赖模块：ZT12、ZT15。对应蓝图：08、18。

## 目标和接入策略

通过官方 SDK/经版本评估的客户端接口接入 Codex。以 Zentwine 业务、权限、工作区和执行对象为中心。SDK 用于程序化工作；App Server 可为自有界面提供会话、审批和事件，但当前官方对命令/WebSocket 传输有实验性及生产限制提示，采用前必须核验并记录风险。[S02][S03]

不能直接向浏览器开放完整 RPC。部分 shell/process 方法不继承线程沙箱；因此所有允许的方法建立 allowlist、逐项权限映射，通用终端由 ZT15 的受控进程服务提供，不能顺手转发危险默认方法。实验功能默认关闭。

## 数据与桥接

Run/Attempt ↔ thread/turn/session 映射；InputResponse ↔ 原生批准或输入；RuntimeEvent ↔ 原生通知。保存 raw_type/schema_version 以便诊断但过滤秘密和无权内容。用户请求模型与实际返回模型分别记录，SDK 与运行时版本一起锁定。

## 验证和回退

无 Key、过期登录、版本不匹配、拒绝工具、消息乱序、审批响应过期、未知 method、资源耗尽、服务端断开与线程损坏均测试。无法安全提供交互审批时，使用固定低权限执行→结束节点→平台审批→新执行，不静默提高权限。

跨基座切换不迁移不可用的隐藏会话，只交接经校验的上下文和产物。目标版本升级先 conformance，再小范围启用，旧 Run 保留旧兼容宿主直到安全结束或显式迁移。
