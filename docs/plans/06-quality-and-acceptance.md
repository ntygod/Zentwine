# 06｜验证策略、完成定义与系统验收

## 1. 验证层次

领域单元测试验证状态、权限、版本与预算；数据库集成测试验证事务、RLS、outbox/inbox；契约测试验证 API、RuntimeAdapter、Connector 和 schema 兼容；浏览器 E2E 验证跨窗口、变更和评审；真实基座测试验证并行、权限、停止与产物；故障/安全测试验证异常恢复。

FakeRuntime 用于可重复的开发测试；真实 Claude/Codex 的验收报告单独保存并标注供应商、模型、运行时、工具和环境版本。没有凭据时 CI 明确 skipped_live，不以绿勾冒充通过。

## 2. 共同完成定义

每项交付需要对应任务 ID、规格/接口版本、代码/文档、正反向测试、权限测试、可观测事件、迁移/回退说明和评审记录。功能关闭或环境不满足时给出明确行为。文档任务完成与产品能力完成分开。

测试配置、预期行为与验收方案的变更由独立角色批准；不能把修改测试后的自测当成旧需求已满足。人工验收也绑定候选版本与人员身份，不只是评论“可以”。

## 3. 验收案例目录

`docs/tests/end-to-end.md` 将蓝图 E01–E40 转成前置、步骤、期望与证据，并增加独立 Studio、多入口、计费和灾难恢复场景。模块文档给出更细的局部测试，不能用系统大场景代替边界测试。

必须完整跑通：同一邀请功能两种模型真实并行；接口产物被下游采用；中途 7 天→24 小时变更；一个必要验证失败；重试不会重复副作用；组合候选验收；按政策发布；效果观察允许未知。

## 4. 可信证据

证据生产者需要可鉴别的 Verifier 身份；固定测试计划、commit set、镜像、依赖与数据摘要。结果缺失、旧基线、超时、环境失败、模型判断分别表示。

证据完整度不等于质量分数；不得自动将模型自述升格。必要证据过时后，决策门禁重新评估。报告中原始输出按权限与保留策略提供，不向所有查看者暴露密钥或私有数据。

## 5. 初始非功能测试目标（提案，非已实现 SLA）

测试环境建议 100 组织、每组织 100 成员、10 万工作包、1000 万业务事件；租户可调小做 PR 测试。普通领域读取 p95 < 500ms，关键命令接受 p95 < 1s，不含模型/供应商响应；事件到 UI p95 < 2s；列表 10 万行采用服务端分页和虚拟化。

Runner 容量单独按 100 并发隔离执行做候选基准，测资源与公平性，不用代码产出速度充当吞吐。停止确认在可杀进程环境内目标 10s；超时必须 unknown/隔离，不能为达标假报成功。具体值在 ZT27 基准后定版，环境配置写进报告。

部署恢复演练建议目标 RPO ≤ 15 分钟、RTO ≤ 4 小时，待负载/部署预算校准；不作为对外承诺。跨区域恢复、数据删除、供应商离线均有专项场景。

## 6. CI 与发布门禁

PR：lint、typecheck、unit、schema、migration、tenant/security smoke、重点 UI；主干：integration、E2E、适配器 Fake；受控计划任务：真实基座、费用受限评估、故障演练。生产前：独立安全复核、备份恢复、许可证/SBOM、供应商版本与数据流核验。

新增测试失败不可自动改为可选。Flaky 测试隔离要有责任、原因、到期和替代保护，不能无限隔离。

## 7. 自动化评估而非模型投票

模型比较固定任务、预算、工具和验收方式，保存样本数、失败模式、人工修正及成本。历史数据不足显示证据不足。规则、真实测试和人工决策共同决定，不采用两个模型相互认可即通过。
