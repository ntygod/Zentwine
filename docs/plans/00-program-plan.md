# 00｜完整产品开发总计划

## 1. 基线、范围与约定

产品：Zentwine 众弦。目标是原生团队研发操作系统，包含经营规划、交付、治理三种管理空间，以及可独立打开的 Zentwine Studio。组织人和不同模型从机会发现到产品效果验证。

本计划依据《团队研发操作系统_终态产品蓝图_v2.0.md》及后续独立 Coding 工作台约定。建设波次只表达依赖，不把终态能力删成 MVP。当前仓库仅初始化 README，无产品代码；下列实现、接口、代码目录均为拟建。

固定约束：真实异构并行；批准版本不可覆盖；人类责任可定位；业务决策、模型推断、工具事实分别保存；一工作区一个有效写入控制者；验证独立；自动化受授权约束；资料可导出和删除。

## 2. 成果分解

30 个模块计划，每模块拆为 6 个编号开发工作包；每个工作包有交付范围和可检查验收。实施者应按模板再拆成一个或少量可评审 PR，不把整个模块当作一次模型调用。

任务 ID 为 `ZT{模块两位数}-{任务两位数}`。模块技术硬依赖见各文档；业务输入可以先使用固定版本的合法 Fixture 并行开发，但联调必须替换为真实实现，不能永久用 Mock 验收。

## 3. 建设波次与里程碑

| 波次 | 重点 | 模块主归属 | 退出条件 |
|---|---|---|---|
| W0 | 契约与工程基线 | ZT01；共享 ADR、状态、协议 | 构建/测试骨架、租户与协议模型、技术验证记录；争议有负责人 |
| W1 | 共同业务、UI 和执行底座 | ZT02、03、04、12、15、18 的基础能力 | 两租户隔离；版本与事件可回放；仓库和工作区可控；无模型也可运行假基座契约测试 |
| W2 | 需求到异构执行的纵向闭环 | ZT06、11、13、14、16、17、19 | 两种真实模型经两个基座并行，发生交接、失败、需求变更并形成真实证据；Studio 独立窗口能接手 |
| W3 | 完整产品与项目工作空间 | ZT05、07、08、09、10、25 | 原生发现、设计、架构、计划、变更都连通；无副作用方案推演通过验收 |
| W4 | 发布、自治与效果闭环 | ZT20、21、22、26、28 | 低风险流程按政策自动交付，保护指标异常能停止；成本全链路核对；效果允许未知 |
| W5 | 多入口、联邦与企业环境 | ZT24、27、29、30 | 外部权威冲突可处理；桌面/IDE 权限正确；私有部署恢复及退出演练通过 |
| W6 | 可扩展、可学习的终态 | ZT23 与所有模块规模化验收 | 插件签名与撤销、工作流回放、学习回退、全 E01–E40 及补充场景通过 |

模块主归属不是禁止提前工作。ZT07 的事件契约、ZT09 的契约格式、ZT26 的预算原语、ZT27 的日志/隔离基线必须前置；完整界面与高级能力再在主波次交付。任何生产执行不能等 W4/W5 才补安全与费用控制。

## 4. 关键依赖路径

`ZT01 → ZT02/ZT03 → ZT12/ZT15 → ZT13+ZT14 → ZT16 → ZT17/ZT19 → ZT20/ZT22`。

业务侧并行：`ZT03 → ZT06 → ZT09/ZT11 → ZT07`；`ZT03 → ZT05/ZT10/ZT08`。真实多模型交付同时依赖业务和执行两条路径，不能只看工具接通。

工程并行建议：A 组身份/业务内核；B 组运行时/环境；C 组 Workbench/Studio；D 组验证/运维。一个人可轮流承担，不假定已有四个团队。API、消息、状态先冻结；实现者通过同一契约 Fixture 协作。

## 5. 三类门禁

**契约门禁**：所有消费者理解对象版本、权限、事件幂等、失败和未知状态。

**功能门禁**：真实用户路径及异常路径可演示，有自动化验证和必要人工判断。

**运营门禁**：日志脱敏、撤权、预算、停止、备份恢复与部署回退经过演练。通过文档检查不等于通过产品门禁。

## 6. 规划与变更治理

负责人首先评审 ADR 和公开部署/许可证选择；任务创建为 Planned，不预填个人承诺日期。每轮从实际人类评审容量、工作区容量和预算拉取 Ready 工作。复杂度用 S/M/L/XL 作讨论，不直接换算工期；首批完成后基于实际数据估算。

新增能力先映射终态和依赖；减少范围需显式变更批准，不能把难题藏在“后续优化”。未知技术通过独立 Spike 获得证据，记录采用/拒绝理由及退路。

## 7. 最终完成判定

所有能力域有真实可用路径；E01–E40 与 Studio、治理补充场景有证据；具备发布和运行手册；真实供应商适配通过目标版本验证；隐私、授权、许可证经过负责人核对；客户能够迁入、使用、撤权和迁出。

不以文档数、代码量、Agent 数量或模拟成功率宣布产品完成。
