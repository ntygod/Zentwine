# 05｜UI、交互与独立 Coding 工作台

## 1. 信息架构

Workbench 的经营规划空间提供机会、目标、路线图、组合与项目沙盘；交付空间提供需求、设计、架构、工作包、执行、代码、测试与发布；治理空间提供模型、知识、流程、环境、预算与审计。

Studio 是一等独立入口，支持当前页、新窗口、桌面和已授权外部 IDE。开发者可设它为默认首页。它不是管理大屏里的终端，也不是供应商 CLI 的像素镜像。

## 2. 路由和共同对象

| 页面 | 预期路由 | 主动作 |
|---|---|---|
| 我的工作 | `/org/:org/workbench/inbox` | 领取任务、处理决策 |
| 产品机会 | `/org/:org/products/:product/opportunities` | 建立目标委托 |
| 项目沙盘 | `/org/:org/projects/:project/scenarios/:scenario` | 比较、批准方案 |
| 交付单元 | `/org/:org/deliveries/:delivery` | 查看需求到结果 |
| 多模型执行 | `/org/:org/flows/:flowRun` | 进入节点、处理阻塞 |
| 变更驾驶舱 | `/org/:org/changes/:change` | 查看影响、批准、跟踪采用 |
| 独立 Studio | `/org/:org/studio/workspaces/:workspace` | 开发、接手、验证、提交 |
| 发布中心 | `/org/:org/releases/:release` | 检查清单、授权、观察 |
| 模型/治理 | `/org/:org/settings/...` | 能力、权限和预算管理 |

链接只定位，不携带 API Key；越权深链显示安全错误。多个窗口共享后端状态，不共享任意本地信任。

## 3. Studio 布局

顶部持续显示项目、交付、任务、规格/契约版本、分支、环境、控制者、自治模式与同步健康。左侧文件/搜索/任务上下文；中央代码、diff、原型与应用预览；右侧当前 Agent 的计划、对话、工具事件和相关节点产物；底部终端、调试、测试和日志。

工作区可跨文件和仓库，但跨仓库写入仍按明确授权。上下文面板给出来源与缺失信息，不自动采集全部私人会话。

## 4. 管理与 Coding 的双向过程

打开任务：检查可见性 → 查找已有关联工作区 → 没有才显式创建 → 加载批准上下文 → GET 只展示。

开始执行：用户选择角色/模型/基座 → 显示权限与预算 → 预留资源 → 创建 Run → 订阅事件。

执行返回：问题、阻塞、变更提案、PR 与实际验证回写任务；普通打字和私人探索不上报为绩效。

中途变更：显示旧/新版本及影响 → 请求检查点 → 确认采用或异议 → 新输入改变时创建新 Run → 重核证据。消息到达、运行时接收、实际采用、重验证使用四种状态。

人工接手：请求交接 → 阻止新工具写入 → 确认旧进程/子进程停止 → 保存快照 → 切换 lease epoch → 人工编辑。若不能确认旧进程停止，工作区隔离为只读，不允许第二写入者。

提交：形成 ChangeSet 和 Evidence 索引 → 创建/关联 PR → 进入评审；不把执行成功自动当作发布完成。

## 5. 关键交互验收

- 新窗口/刷新/返回管理端不创建额外 Run；关闭窗口不隐式取消云端执行。
- 关闭前解释执行所在环境及是否继续；本地休眠不能显示仍在执行。
- 请求停止与已停止不同；未知状态有原因和处理动作。
- 只读观察者能看获授权产物，不能通过终端或预览绕过控制权。
- 两个用户同时接手，最多一个成功；冲突者看到当前控制者和版本。
- 外部 IDE 未同步内容显示不可见，不假装拥有全部本地信息。

## 6. 设计系统与可访问性

统一 spacing、typography、语义颜色和状态组件；浅色/深色/高对比主题。键盘导航、焦点恢复、屏幕阅读器标签、中文输入法、多语言长文案与响应式均要测试。移动端偏向决策、预览与轻编辑，不强行压缩桌面 IDE。

此前 AI 生成 UI 仅是视觉方向：示例进度、模型版本、评分、费用、日期、合规认证、已验证数字不可作为真实产品事实。进度用可解释分母；审计状态与表格合计必须一致。没有校准依据不显示永久模型排名、自动健康分或确定工期。
