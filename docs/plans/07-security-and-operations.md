# 07｜安全、可靠性、部署与运营基线

## 1. 威胁模型

保护资产：客户源码和业务资料、供应商密钥、组织身份、批准版本、代码写权限、发布凭据、费用额度和证据真实性。威胁来源包含恶意仓库文件、工具返回、插件、越权成员、失控 Agent、受污染依赖、旧执行和错误连接器。

边界：浏览器/桌面、业务控制面、Runner、执行沙箱、Verifier、外部系统、供应商。每条数据流记录目的、字段、区域、保留与撤销方式。第三方内容是数据，不能改授权。[S07]

## 2. 访问控制

角色权限＋组织/项目/资源范围＋动作＋数据等级＋环境限制。Agent 权限是主体授权与组织策略的交集；子执行只能收窄。关键动作前重新检查撤权，不能只相信启动时快照。

数据库 RLS 可作为第二层隔离；运行连接角色不能有 superuser/BYPASSRLS，表所有者与迁移身份隔离，并测试 owner 绕过行为。[S05] 应用仍做领域鉴权，不能只靠数据库隐藏按钮。

## 3. 执行隔离

沙箱默认非 root、限制网络/CPU/内存/磁盘/进程，禁止暴露宿主 Docker socket 和元数据凭据；仓库钩子与依赖安装视为不可信代码。跨租户使用强隔离验证；worktree 仅组织 Git 状态，不提供安全边界。

文件服务校验真实路径、符号链接和目录穿越，TTY/预览/LSP 都受同样权限。预览使用独立来源与认证代理，防止应用 JS 读取管理端会话。网络出口校验重定向、DNS 变化和私网地址。

## 4. 凭据与外部工具

用密钥引用而非明文；凭据代理按短期、最小范围发放。允许动作和限制在工具端/沙箱执行，不能只依赖模型服从提示词。供应商 App Server 不暴露公网原始控制口。

Webhook 验签、去重、速率控制和重放保护；入站快速确认后异步处理。无法判断远端操作成功时进入 unknown 并对账。[S08]

## 5. 自治与预算

分辅助、委派、受控交付、持续运营。授权绑定目标、资源、版本、动作、预算、有效期、验证、停止条件。新增角色/模型/工具先评估，再扩大范围。模型不自行提高自治等级。

预算执行使用预留、确认、释放与对账，覆盖子 Agent、重试、Verifier、计算和存储。硬阈值停止新授权，同时明确在途支出可能继续结算。密钥撤回不能被应用层“停止”替代。

## 6. 日志、审计与隐私

操作事件与模型工具日志分开保留；日志脱敏，不默认收集全部私人会话或模型内部思维。审计记录动作、主体、对象版本、授权与结果。对安全管理员也限制业务内容访问。

删除工作流覆盖源、缓存、搜索、向量索引、派生摘要、导出与未来上下文。备份中的删除通过到期、加密销毁与恢复后清理策略处理，保留必要证明；不承诺瞬间抹除供应商已接收数据。

## 7. 运维和恢复

部署模式：开发 Compose、托管、企业专属、私有和混合；离线只使用可验证离线组件。持久数据采用加密备份与恢复演练，迁移 expand/migrate/contract；先兼容读写再移除旧字段。

API/Worker/Runner 各有就绪、心跳、版本与资源状态。日志全链路 correlation，但不把租户高基数敏感信息无控制写入指标。告警按积压、失败、预算、租约/授权异常和证据失效配置。

事件重放只重建投影，不重放真实发布/通知。恢复后先核对外部系统与租约，再重新调度。全局应急停止可撤销令牌、停止新调度、冻结发布；无法停止的执行进入隔离与人工清理。

## 8. 上线阻断事项

真实跨租户泄漏、无授权写入、不可控后台进程、伪造验证、无法恢复数据、未知许可证或违规认证复用均为上线阻断。计划中的认证能力不能在 UI 展示为已经获得 SOC 2 等认证。
