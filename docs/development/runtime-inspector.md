# Studio 本地交接检查台

ZT12-01-A7 / Issue #59。此入口检查手动选中的本地文件，不是运行宿主或组织数据入口。只在本地 Studio 首页（`/` 或 `/org/local/studio`）提供；未知工作区仍拒绝进入。打开页面或检查台不读取文件、不创建 Run。

## 操作

启动现有开发环境后，在 Studio 点击“检查本地交接包”。选择 `plan.json`，为每个生产清单明确选择对应的 NDJSON 事件文件，为每个消费输入明确选择原始产物文件；不按文件名猜测映射。全部选择后点击“开始本地检查”。

检查台真实调用 RuntimeInputBundle：先等所有生产报告完成，再打开产物流，核验全部输入字节。成功显示“字节校验通过（未授权执行）”，失败显示拒绝，任一失败都不交付部分内容。仅显示元数据，不预览正文，不调用 takeAll，不下载或执行原始内容；结束立即关闭整批读取器、释放内部缓冲和所选文件引用。浏览器持有的源 File、平台密码副本或操作系统文件不承诺擦除。

“清除文件与结果”、关闭检查台和卸载会取消旧读取并清空界面。迟到的计划读取结果和旧检查结果不能恢复或覆盖新选择。刷新不恢复选择。取消本地读取不等于停止任何远端进程；本页根本不启动远端执行。

## 文件格式

```json
{
  "inspection_version": "1.0.0",
  "consumer": "替换为完整 wire1.0.0 StartRun 对象",
  "producers": [
    {
      "request": "替换为该生产者的完整 StartRun 对象",
      "manifest": "替换为该生产者的完整 ArtifactManifest 对象"
    }
  ]
}
```

上述字符串是格式说明，不是合法运行请求。计划最多 262144 UTF-8 字节，使用现有严格 JSON 解析器，拒绝重复解码键、BOM、非法数字、超深/超多节点、未知封装字段或版本。再用原 A6 构造预检完整输入覆盖、组织/Run/Attempt/来源/版本/摘要及总预算。不是把上传文件中的组织 ID 当授权。

事件文件遵循 A3：每行一个完整事件，最后一行也有换行；每份最多 4MiB。产物选择不能超过声明长度，实际检查仍验证 EOF、精确长度与 SHA-256。A6 的 16 输入、8 生产者及 16MiB 总声明上限与所有原读取限额保持。

## 无模型示例

仓库内显式执行以下命令生成两生产者、两输入的合成示例；目标目录必须尚不存在，不覆盖已有目录或文件：

```sh
node scripts/runtime-inspection-example.mjs /tmp/zentwine-inspection-example
```

按序选择生成的 plan.json、producer-1.ndjson、producer-2.ndjson、input-1.bin、input-2.bin。示例只供检查路径练习，应用不会自动加载它。任意改动 input 文件的一个字节可验证拒绝路径。此命令不需要模型凭据或运行模型。

来源仍为未认证报告，产物 verification:unverified，authorization:false。结果不是代码安全证明、需求验收、真实多模型协作、生产存储或文件访问授权。本地诊断也不解除 Issue #25 的完整文件/预览/导出验收或 #32/#35/PR #33 的持久化阻断。
