# ZT04-02｜组织深链与授权导航

## 入口与实际范围

工程首页增加“组织工作台”入口，打开 `/org/local/workbench/organizations`。需要已启用现有身份、策略、审批和组织服务；未启用则明确展示不可用，不提供样例组织。没有新数据库迁移或自动安装行为。

稳定深链为 `/org/<UUID>/workbench`、`/org/<UUID>/workbench/catalog` 与 `/org/<UUID>/workbench/governance`。分别读取当前身份概览、真实有权访问的目录以及负责人只读组织设置。路径只接受小写UUID和这三个视图；未知业务路由返回页面不存在，不推导权限或构造任意API地址。刷新和浏览器前进/后退使用普通文档导航，无第三方路由依赖。

治理页面只读。成员/邀请/审计/应急操作仍由现有 `/org/local/workbench/settings` 控制台负责，它会独立重读当前会话及权限；该旧入口是本机登录和组织管理入口，不是新深链的授权凭证。Studio仍独立；未实现的项目、需求、执行不出现可点击伪入口。

## 会话和切换

所有读取使用同源HttpOnly会话、no-store及有界超时；组织请求携带从服务器读取的context_version。先读取能力/会话，再读取指定组织的organization-self；角色决定当前导航。负责人之外直接打开治理URL不会挂载治理组件或发出设置读取；服务端原设置API仍独立拒绝越权，前端隐藏不替代授权。

若深链组织不是会话选中的组织，只显示明确切换确认；不因GET、刷新或历史恢复自动发起POST。不存在或不在组织列表中的组织显示统一不可访问。明确切换使用原有Origin/CSRF保护的组织选择命令、当前expected_version，并检查返回的组织、会话、人员及版本；成功后到固定构造的组织概览路径。未知写入结果不自动重试，需重新核验服务器状态。退出登录也是明确命令。

## 清理与错误边界

每次读取或切换先同步发布loading状态，移除旧成员名、目录、治理内容、查询输入和导航，再发出请求。Abort加单调请求代次同时使用，即使旧请求忽略取消晚到，也不能重新填回旧结果。每个路由/窗口持有自己的内存快照，不写localStorage、sessionStorage或额外cookie，不持久缓存租户内容。

离线、隐藏和pagehide使旧状态失效；focus、pageshow、回到可见页和online重新核验。浏览器事件仅触发失效/读取，不携带或决定权限；本增量没有跨窗口权威缓存或消息授予权限。页面明确标注按次核验快照，非实时推送。持续可见但没有新请求的另一窗口可能暂留已经返回的旧快照；ZT04-04的实时撤销通知尚未实现，不声称远程收回已返回数据。页面终止/系统截图不属于应用可抹除的范围。

匿名、服务关闭、请求中、组织待选择、无条目、无权限、版本冲突、网络失败、格式错误和暂停分别展示。错误只使用固定本地文案，不回显服务端原始错误。React渲染失败沿用共享AppBoundary覆盖整页；受保护内容只在已核验ready状态挂载。切页采用完整文档导航，主题按ZT04-01约定重新跟随系统。
